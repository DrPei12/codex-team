# 已接受的设计决策

[English](13-decisions.md) · [简体中文](13-decisions.zh-CN.md)

当前定义与本页已接受决策指导实现，历史决策在 Git 历史中保留原适用背景。

| 决策 | 依据与效果 |
|---|---|
| D-070：Codex-only，承接跨领域任务 | 执行平台保持明确，方法与验证服从任务；核心无第三方 Skill 或插件依赖。 |
| D-071：自然沟通与持续演化的定义 | 模型选择有用的交流方式，主动把已采纳想法融入连贯定义；工作笔记与原始历史支持接续。 |
| D-072：自主执行与渐进规划 | 总体责任持续明确；工作、尝试、接收与会话分开记录，计划随证据展开。 |
| D-073：持久自适应运行程序 | SQLite 命令、原生执行、可读队列、局部变更与有证据的接收构成运行基础。 |
| D-074：临时局部协调 | 已有成员可获得明确工作范围，调整组织、接收其他成员成果并交还职责；不能扩大自身权限或接受自己产出的成果。 |
| D-075：稳定身份与独立推进 | 成员身份跨角色变化保持稳定；会话可在执行与协调间切换，替换时保留交接。互不影响的变更自动合并，受影响的活跃工作等待稳定边界。 |
| D-076：现场占用与外部动作身份 | 跨状态目录的现场占用保留到未知执行完成核对；外部写入使用稳定动作记录，重试前检查目标实际结果。 |
| D-077：英文优先的双语分发 | GitHub 当前目录保留产品源码、可安装包、测试和中英文文档；历史试验场移出当前目录，在 Git 历史中保留。 |
| D-078：预算预留与准确恢复 | 分派时通过事务预留预算，未知执行保留预留。恢复时核对原生会话、回合、项目、目录和执行策略，再释放占用。明确撤销时中断临时协调回合，其他成员继续工作。 |

D-074 至 D-078 于 2026 年 9 月 15 日根据用户的正式版执行委托采纳。发布版本与项目定义版本分别管理。1.0 以原生会话作为执行单位；局部协调与其他工作使用同一模型和资源策略。
