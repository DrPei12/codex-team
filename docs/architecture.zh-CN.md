# Codex Team 的运行原理

[English](architecture.md) · [简体中文](architecture.zh-CN.md) · [首页](../README.zh-CN.md)

## 统一的公开入口

Team skill 承接目标讨论、执行、方向调整与交付，内部运行指引供模型按当前工作需要读取。`scripts/team.py` 与 `python -m team_runtime` 调用同一个 CLI。规划和完成工具属于内部能力，不再单独提供阶段 skill 或其他控制器。状态格式 0.3 与发布版本分别管理，本次升级继续读取原记录。

## 先理解委托，再组织工作

入口运行在用户的 Codex 对话中，将委托整理为连贯的项目定义，调查缺失事实，并建议执行安排。用户的明确修订与已采纳想法进入正式定义；工作笔记保存继续位置，原始历史保存判断与证据。

组织方式由讨论和任务决定。调查、实现、审查与集成在有明确成果或交接价值时形成工作事项。简单任务可以让同一个原生成员兼任执行与总体协调，独立工作较多时则在资源策略内增加成员。

## 四种身份分别记录

| 记录 | 作用 |
|---|---|
| 工作 | 目标、验收依据、依赖、责任与当前状态。 |
| 成员 | 稳定的参与者身份，可以在不同任务中改变角色。 |
| 执行尝试 | 一次实际原生执行，记录会话、回合身份及其结果。 |
| 接收 | 判断特定成果满足验收依据，保存理由与内容身份。 |

失败尝试留在历史中，替换会话从当前笔记、定义和产物接续原工作。成果被接收后才能成为后续工作的有效依赖。

## 自适应职责

每次运行保留对目标和交付负责的总体协调职责。成员可以直接交流，建议调整分工；总体协调者可将一组明确工作委托给已有成员协调。

局部协调者可以检查并接受其他成员的成果、修改范围内的工作，并在已委托目录与写权限内增加后续工作。它保留验收标准，不能扩大自己的委托范围，也不能接受由自己成员身份产出的成果。范围内成果全部被接受后，委托自动结束；提前交还时记录结束理由。

角色不是永久职位。成员的原生会话可以从调查转为只读协调回合，再接续下一项已授权执行。替换会话时保存交接记录，成员的历史继续存在。

## 模型判断与程序职责

模型判断委托的含义、协作是否有用、采用什么方法以及成果质量。运行程序维护持久记录，通过明确的状态变化落实这些判断。

`team_message` 分享信息，`team_request` 登记排队协助，`team_propose` 保存组织建议，`team_delegate` 委托局部职责。`team_change` 版本化调整计划，`team_accept` 绑定接收成果，`team_finish` 请求整体交付。工具权限依据当前有效职责检查。

## 派发与协调

调度器检查依赖、成员是否空闲、目录冲突、停止意图和资源策略。发给忙碌成员的请求排队，不注入其当前回合。排队老化机制提高反复等待的可执行工作的位置。独立目录中的局部协调可以与其他执行同时推进，总体协调需要对项目保持稳定的读取条件。

计划调整明确受影响工作。旧版本请求引用的工作与定义没有改变时，可以自动合并互不影响的调整；涉及已改变或活跃工作的调整，需要复核或等待确认的执行边界。已接受证据保持原版本绑定；证据失效时，仅相关依赖后继进入复核。

## 持久状态与恢复

SQLite 事务一起提交状态、事件、派发记录和命令回执。同一身份的重复命令返回原回执，同身份但内容不同则返回冲突。程序先保存派发意图，再启动原生执行；先保存会话绑定，再启动回合。

控制租约标识当前负责派发的进程。租约到期不会直接清除原生执行。恢复核对查询原生会话与后台终端，保存观察结果和当前文件后继续。

同一用户的现场登记表协调不同 Team 状态目录之间的占用。重叠项目不能针对同一实际现场启动独立控制程序。执行未知时保留占用，确认收口或恢复核对后释放。登记表位于 `~/.codex-team/workspaces.sqlite3`。

## 外部动作

成员执行原生外部写入前，通过 `team_effect` 登记稳定动作键、目标和描述。首次登记允许一次尝试；再次登记同一动作时，要求检查目标。动作已执行但回执丢失时，通过观察原操作，记录 `succeeded` 或 `not-applied` 及其依据。未知结果阻止相关工作接收和最终交付。

账本保存操作身份与观察结果；实际服务通过成员已有的原生工具、在用户授权范围内访问。服务回执、幂等键和状态查询提供核对依据。

## 上下文与可见性

当前定义、职责、已接受成果与最近消息组成执行背景。成员维护工作笔记，通过关键词和游标检索原始事件，大型产物按内容哈希定位。Codex 对话通过 CLI 状态快照和历史查询汇报进展，并提供原始回执。

## 使用时更新版本

Team 在开始或恢复对话时调用内置更新程序，检查官方 GitHub 正式发布，缓存检查结果并保存自动更新、仅通知或关闭的偏好。更新说明作为描述性数据，每次变化只提示一次。未固定版本的官方 Git 安装，默认自动更新到同一主版本内的兼容发布。

安装前核对下载文件与安装包清单的哈希，再调用 Codex 原生 `plugin/install`。共享 SQLite 读锁保护运行中的控制程序；安装取得独占锁，并检查跨状态目录的工作区登记，包括旧控制程序和结果未知的执行。安装期间保持登记表事务。插件缓存之外的旧安装包与独立安装日志支持结果核对和失败恢复。注册的 marketplace 与项目状态保留，Team 改用返回的新 skill 和运行程序路径。

## 源码位置

| 源码 | 职责 |
|---|---|
| `adaptive.py` | 工作、尝试、接收、计划变更与控制。 |
| `coordination.py` | 建议、局部委托、交接与动作记录。 |
| `adaptive_runner.py` | 原生 Codex 会话、动态工具与调度。 |
| `workspace_claims.py` | 跨状态目录的现场占用。 |
| `store.py` | SQLite 事务、事件、回执与版本检查。 |
| `policy.py` | 资源配置与有限额度校验。 |
| `redaction.py` | 原生观察记录中的凭据脱敏。 |
| `cli.py` | 在 Codex 中使用的持久化运行命令。 |
| `updates.py` | 正式发布检查、更新偏好、原生安装与恢复。 |
| `skills/team` | 自然语言入口与运行指引。 |

运行模块位于 [`team_runtime`](../team_runtime)，可安装插件在 [`plugins/codex-team`](../plugins/codex-team) 中携带这些模块与入口。
