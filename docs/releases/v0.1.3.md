# Codex Team 0.1.3 — Coverage, backbrief, and checkpoints

## New Features

- **Requirement coverage**: Every frozen requirement binds an owner, implementation or verification path, Gate, and reviewer. Ownership orphans fail before dispatch.
- **Worker backbrief**: A worker must acknowledge exact requirements, ownership, Gates, exclusions, and its first bounded action after preflight and before implementation.
- **Stage checkpoints**: Dependency completion no longer automatically unlocks the next lane when exact checkpoint evidence is still pending.
- **Material progress**: Status facts distinguish activity from progress using manifest-specific heartbeat and turn budgets.

## Improvements

- Failed backbriefs remain reviewable failure receipts; unresolved assumptions/questions stop as `needs-input`.
- `change` and `verification-only` requirements avoid inventing writable owners for negative invariants.

## Breaking Changes

- 0.1.3 adds required requirement, checkpoint, progress, and backbrief fields. Historical manifests/facts are not automatically upgraded.

## Evidence and limits

Nine suites passed 144 source tests; 16 offline end-to-end artifacts passed schema validation; the final temporary plugin passed 7/7 skill validation and a 37-file/7-entrypoint self-check. No 0.1.3 Desktop live fact collector, worker backbrief/checkpoint forward test, background scheduler, or automatic task interruption is claimed.
