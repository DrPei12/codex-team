# 0.3自适应Team Plugin预览实现

实现与实验：2026-09-14；回归和本机安装收尾：2026-09-15。方向基线为项目定义v0.4及D-072；本轮用户授权正式实现，并为真实实验提供最多5个百分点、统一Luna/max的额度。当前是可运行的预览实现，不是22项设计验收全部完成或长期无人值守可靠性的声明。

## 已实现的使用链路

Team入口在Codex对话中理解委托、提供建议并维护完整目标定义，采用工作笔记与原始历史检索。入口不新增固定澄清模板、开场模式选择或反复授权。形成初步执行安排后，包内`team-next.py`登记普通目录或软件仓库中的项目，调用已登录的官方Codex，不需要第三方Skill、插件或API Key。

运行程序以真实原生项目关联会话。工作、执行尝试和接受记录分别保存，协助请求进入同一队列，等待者结束回合让出执行能力；答案提交后由协调责任核验，再解除依赖。一次执行结束不等于工作被接受。模型负责提出工作调整和质量判断，程序负责动作、身份、版本、停止意图和结果引用的一致性。

SQLite命令把实体、事件、派发记录和命令回执放在同一事务内；相同命令重试返回原回执，同键异内容拒绝。派发先持久化，线程绑定先于回合启动；无法确认停止时保留未知状态。工作引用实际文件哈希，来源材料和工作笔记可沿原始事件查询，不将摘要链作为唯一历史。

局部调整保存旧工作内容及理由。接受证据失效时保留原接受记录，只让其依赖后继进入复核。用户新消息发生在协调判断之后时，旧判断不能直接完成Run。已经完成的Run不吞掉新委托：新工作须建立后继运行。

本地中文看板读取相同状态库，展示完整定义、工作责任、等待关系、对话、笔记、原始记录、实际结果与接受身份。可以继续、暂停、结束或核对恢复现场。请求已保存和原生已停止分开显示；看板运行不等于控制程序正在推进。

## 实际验证与证据

程序检查使用真实SQLite、多进程退出、CLI子进程、本地HTTP和文件系统。原生RPC超时的可控故障用明确标注的测试替身；它不能代替真实Codex资格化。测试位置为`tests/test_adaptive.py`和`tests/test_adaptive_boundaries.py`，保留全部旧协议测试。按仓库CI约定运行，旧版九组149项及运行时173项、39个子测试全部通过；软件产物另有6项真实CLI测试通过。直接用pytest默认临时目录运行旧规划投影用例会违反其既定实验根约定，诊断保存在regression-triage.txt，未放宽产品校验。运行日志和实验摘要在`artifacts/adaptive/20260914/`；完整原始状态位于实验摘要记录的本机state目录。

研究实验为非Git普通目录，任务是比较链接、摘录和原文快照的资料保存策略。研究者实际检索W3C及美国国会图书馆来源；发生真实协作请求、暂停与现场核对、来源工作合并及局部计划调整，最后生成decision.md并由协调者接受。失败、干预及重复工作均保留在原始事件中，不按“一次运行即成功”呈现。

软件实验为CSV→SQLite导入工具，要求真实文件、子进程、中文/BOM、输入校验、冲突和批次回滚。最终在账户82%时停止为paused，最后尝试为interrupted，停止后主任务实际运行6项CLI→SQLite测试全部通过；未补造软件场景的模型接收和completed状态。研究场景成功不能代替软件场景验收。

实际浏览器检查了看板状态、成果展开及URI原始记录检索，未观察到浏览器控制台错误。390像素窄屏加载后的文档宽度375像素，无横向溢出；布局和文本经过实际截图检查，测试后已恢复默认尺寸。这是操作者验证，不代表用户本人视觉接受。

插件采用完整可移动包，验证器与bundle-self-check检查60个文件及9个程序入口。版本为0.3.0预览，旧0.2及0.1.x入口保留原语义。已通过本地codex-team-local marketplace安装至Codex缓存0.3.0，安装后自检通过；原生skills/list确认7个带codex-team前缀的入口均enabled。验证未启动模型回合，见installation.json。主仓库原0.1.0构建包完整保留在.codex-local/plugin-backups/codex-team-0.1.0-20260915。

## 实测暴露的问题与修正

1. 只读沙箱未确认shell联网，但原生网页搜索是另一能力。请求配置现已分开，使用实际返回的沙箱事实校验；不因为研究需要联网就授予可写权限。
2. 原生token总数包含每次携带的上下文，不能换算成账户百分点。早期内部总token防护过低，曾触发提前暂停；保留旧策略与停止记录，在同一账户上限内调整内部防护。账户基线77%、收口预留81%、上限82%；百分点是共享账户观测，不能作为本任务精确计费。
3. 原生中断请求可能超时而终态事件已到达。运行程序对同一回合仅请求一次中断，并核对终态；旧未知尝试通过原生idle和空后台终端核对后恢复，不能凭租约过期重启写入者。
4. 一名执行者将发送答案误用为新协助请求，产生额外工作；协调者也曾在只读责任中尝试写作。修正工具与回合上下文说明：最终答复自动成为结果，只有新行动才登记请求；协调者在接收或调整后结束回合，让已有执行责任继续。此次浪费记录没有删除，这一非确定性行为仍需更多场景观察。
5. 看板保存消息失败时保留草稿，刷新保留已展开记录，长任务文本可展开阅读；已完成运行收到新委托时返回明确冲突，避免静默不执行。
6. 收尾发现回合绑定会把已核对的模型配置覆盖为空。修正后，尝试、会话和绑定事件均保留配置，并补充回归检查。旧实验记录没有补造配置；从5个实际会话的原始turn_context记录单独导出模型证据，均为gpt-5.6-luna/max，见native-model-evidence.json。

## 当前能力边界

本轮采用独立Codex会话，运行程序明确禁用内部Subagent。策略中的子代理数是上限，不表示该生命周期已得到验证。未注册子执行、复杂后台作业、长期无人值守、全局写现场冲突及自动会话替换仍需后续独立资格化。当前一个state内防止同一workspace重复活动Run；不同state指向同一现场仍由宿主避免，不能并行开启两个控制域。

完整目标定义更新当前要求所有活跃尝试到达确认边界；一般计划修改按受影响工作串行检查，尚未实现不相交变更自动rebase。接收仍需要模型或委托操作者的实质质量判断，文件哈希不能证明结论正确。对外动作状态未知时必须保留现场、核对目标，不能盲目重发；未资格化的高影响外部动作交回宿主在真实权限与记录下处理。

这版提供了可运行的基础和可追溯的实验结果；尚无对照实验可以证明多会话更省额度或质量普遍更高。后续优先补齐外部动作恢复和复杂交接，继续观察信息/行动误分类和协调开销，再扩大真实任务类型。
